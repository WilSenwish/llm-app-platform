# Trade-off（第 1 周）

记录这一周真正做过取舍的决定。后面周次在本文件追加，不另起炉灶。

## 1. 三层执行器，而不是把路由塞进 PluginExecutor

| 方案 | 结果 |
| --- | --- |
| 一个 `PluginExecutor` 同时路由、查找、执行 | 否决。测试要分别钉住“没路由”和“插件不存在” |
| 前置编排 → 调度 → 执行 | 采用。三层各自返回 `PluginResult`，不把业务失败抛成异常 |

代价：一次请求多两次方法调用，并多两个 Span。这个开销相对模型调用可以忽略。第 3 周的超时和熔断放在执行层，不回到编排层。

## 2. Spring Bean 优先，SPI 同 ID 跳过

| 方案 | 结果 |
| --- | --- |
| 只扫 Spring Bean | 否决。路线图要求 `ServiceLoader`，否则没有 classpath 插件这份契约 |
| 只走 ServiceLoader | 否决。现有插件已经是 Spring 组件，硬拆掉会让测试和后续网关装配变笨 |
| Spring 先注册，SPI 发现同 ID 则丢弃 | 采用 |

代价：SPI 仍会把重复类构造出来再扔掉。第 1 周插件没有外部连接，这个浪费可以接受。运行时卸载、再加载一个新 jar 没做。

## 3. 内存哈希向量，而不是现在就上 Milvus / Ollama

| 方案 | 结果 |
| --- | --- |
| 直接接 Milvus + Ollama | 否决。闭环会被环境拖住，单测也无法离线复现 |
| 字符二元组哈希到 1024 维，进程内余弦检索 | 采用 |

代价：只认字面重叠，不认同义改写。“如何加载插件”和“插件的装载方式”可能互相召不回。向量维度用 64 时，无关英文和中文文档的余弦仍能到 0.49，证据阈值失真，所以定在 1024 维，阈值 0.25。数据在进程内，重启即丢，多实例不共享。

## 4. 抽取式拼接，而不是假 LLM

回答只拼接召回片段。没有证据就返回 `NO_EVIDENCE`。不在插件里写一个假装生成的模板，避免第 2 周接网关时分不清哪些结果是编出来的。

重排、真实 Embedding、生成，都留到模型网关之后。

## 5. 显式 pluginId 不做低基数指标

`payload.pluginId` 来自请求。如果把它放进低基数标签，调用方每换一个字符串就多一条时间序列。前缀路由命中的 ID 来自代码里的路由表，可以做低基数；显式 ID 只进高基数标签。未注册插件在调度 Span 上记成 `unregistered`。

## 6. 模型网关独立成进程入口，插件只看见 ModelGateway

| 方案 | 结果 |
| --- | --- |
| RAG 直接调 Ollama | 否决。端点、超时和降级会漏进插件 |
| 网关只做 HTTP 转发，生成仍留在插件里 | 否决。降级测不到「请求 → 网关 → 内核 → RAG」 |
| `platform-core` 定义 `ModelGateway`，`gateway-service` 实现路由；RAG 从 `PluginContext` 取到它 | 采用 |

代价：网关模块依赖 `plugin-rag`，因为当前进程把 HTTP、内核和 RAG 放在一起启动。插件反过来不能依赖网关，避免循环。真要拆成两个进程时，把 HTTP 客户端实现成同一个 `ModelGateway` 即可，插件代码不用改。

限流是进程内令牌桶，多实例不共享。第 3 周如果上 Redis，配额应挪过去。重试不额外扣配额，一次 HTTP 请求只扣一次。

Ollama 与 OpenAI 兼容协议都用 JDK `HttpClient` 实现，单测打到本机 `HttpServer`。默认 `mvn test` 不连接真实模型。

## 7. 没证据不调用模型，模型失败不退回拼接

召回分数低于阈值就返回 `NO_EVIDENCE`。有证据但端点全挂时返回 `MODEL_UNAVAILABLE`。不用「根据检索到的资料」把故障伪装成回答。没有装网关的单测和 SPI 加载仍走拼接，避免第 1 周闭环被网关绑死。

RAG 的 HTTP 任务是同步补全。SSE 只透传模型 token，检索结果还不会逐字流到客户端。
